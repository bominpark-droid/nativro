# 자주 나오는 상황과 대응

| 증상 | 대응 |
|---|---|
| `--render` 했는데 "AI판단.json이 원고와 맞지 않습니다" | 원고 파일이 바뀌었다(재저장·재출력 포함). 재판단 필요 |
| `--check`에서 assigns 누락 | 그 id들만 다시 판단해서 배열에 추가. 처음부터 다시 할 필요 없음 |
| 브리핑 글자가 "오 디 오 북"처럼 벌어짐 | 시스템 한글 폰트를 못 찾은 것(`KFONT`가 None). 폰트 설치 후 재렌더 |
| 음표(♪)나 기호가 안 보이거나 깨짐 | 폰트에 없는 글자. `_glyph()`가 자동으로 대체 글자(■, -)로 바꾼다. 로그 확인 |
| `[진단] 깨짐 [12, 13]` | 그 페이지는 대사 감지에서 제외됐다. 본문 페이지면 수동 처리 필요 |
| 스캔본이라 자동 중단됨 | OCR을 먼저 돌려 텍스트 레이어를 만들어야 한다 |
| `credit balance is too low` (방법 2) | 코드 문제 아님. 콘솔에서 충전하거나 방법 1로 전환 |
| 위치 매칭 실패 건수 > 0 | 해당 페이지 원문의 특수문자·줄바꿈 확인. 하이라이트만 누락되고 나머지는 정상 |
| `[배치] 자리를 못 찾은 건수`가 많음 | 삽화가 많은 그림책이면 정상 범위. `gutter: "auto"`면 자동으로 여백띠가 붙는다. `off`로 해뒀다면 `auto`로 바꿔 재실행 |
| 배치 실패가 페이지 전체에서 발생(삽화 없는 일반 도서인데도) | 페이지에 재단 프레임·배경 도형이 있고 그게 "내용"으로 잘못 인식된 경우. `occupancy()`의 절반-면적 필터가 정상 작동하는지 확인 |
| 화자 라벨이 세로로 한 글자씩 쪼개짐 | 배치 폭 후보가 너무 좁게 잡힌 것. `place_label()`이 아니라 범용 `place()`로 라벨을 그리고 있지 않은지 코드 확인 |
| 여백띠를 붙였는데도 실패가 남음 | `GUTTER_W`를 늘려 재실행(150 → 200 등). 그래도 남으면 그 페이지는 삽화 밀도가 극단적으로 높은 것 — CSV·브리핑에는 남으니 수동 확인 |
| narrative/mixed 모드인데 따옴표 없는 대사가 안 잡힘 | AI가 지목한 anchor가 원고와 글자 하나라도 다르면 코드가 폐기한다(지어낸 문구 방지). `_작업설정.json`의 `special`에 해당 구간 힌트를 더 구체적으로 적어준다 |
| `--sound-only`인데 화자 라벨이 나옴 | 발생하면 안 되는 상황. `version` 인자가 `render_pipeline`에 제대로 전달됐는지 확인 |
| 방법 1로 작업 중 Claude Code가 원고를 여러 번 읽어 토큰이 많이 나감 | `--export-tasks`를 안 거치고 원고 PDF를 통째로 읽힌 것. 반드시 판단요청서를 거칠 것 |
| 방법 2인데 구독 토큰이 나감 | Claude Code에게 "원고 본문은 읽지 마"를 안 붙인 것. 실행 결과 로그만 보고하라고 명시할 것 |
| 이미 검수 끝낸 `_AI판단.json`을 실수로 덮어씀 | 방법 1로 재판단하기 전 항상 백업. 스킬은 사용자 확인 없이 덮어쓰지 않는다 |

## 에러 대응

- API 인증 에러 → `.env` 존재·키 형식 확인 안내
- **크레딧 소진**(`credit balance is too low`) → 코드 문제가 아니다.
  console.anthropic.com → Plans & Billing 충전 안내. 캐시가 있으면 렌더는 그대로 가능.
- JSON 파싱/응답 잘림 → `CHUNK`를 40 → 30 → 25로 낮춰 재실행.
  단 `Expecting ',' delimiter` 류는 잘림이 아니라 모델이 만든 JSON 형식 오류다.
  재시도 로직(analyze_book/assign_chunk/analyze_sound/find_narrative)이 1회 자동 재시도한다.
- 수정 후에는 반드시 같은 원고로 재실행해 결과 수치가 유지되는지 확인한다.

## 판단 방법을 바꿔도 되나?

된다. 판단 결과는 `_AI판단.json` 한 곳에만 모이므로:

- 방법 2로 판단해두고 → 나중에 레이아웃만 `--render`로 다시 뽑기 ✅
- 방법 1로 판단해두고 → 그 JSON을 다른 PC에 복사해 `--render`만 하기 ✅
- 이미 검수까지 끝낸 JSON이 있는데 다시 판단하기 ⚠️ — **덮어쓰기 전에 백업**할 것

## 산출물의 한 쪽이 통째로 비어 보인다 (2026-08-02)

**대개 파일 문제가 아니라 뷰어가 아직 못 그린 것이다.** 그림책은 쪽마다 7~8MB짜리 PNG가
들어 있어, 미리보기에서 빠르게 스크롤하면 주석(라벨·씬 카드)만 먼저 그려지고 그림·글자는
늦게 올라온다. 그 순간을 캡처하면 "텍스트가 사라진" 것처럼 보인다.

확인 방법 — 추측하지 말고 기계로 본다:
```python
import fitz
d = fitz.open("산출물.pdf")
p = d[문제쪽 - 1]
print(len(p.get_text()), len(p.get_images()))   # 0 이 아니면 파일은 정상
```
렌더 마지막의 `[최종검증]`이 `✓ 원본 글자 … 전부 산출물에 그대로 있음`을 냈다면 파일은
정상이다. 그래도 의심되면 그 쪽만 `get_pixmap(dpi=100)`으로 PNG를 뽑아 눈으로 본다.

**진짜로 내용이 빠진 경우**라면 `[최종검증]`이 `✗ 원본 글자 누락` 또는 `✗ 원본 내용이
옅어지거나 사라진 쪽`을 낸다. 그때는 산출물을 내보내지 말고 원인을 먼저 잡는다.

## 대사에 쪽번호 숫자가 섞여 있다

`“…누구로 대결6362하지?”` 처럼 대사 안에 쪽번호가 끼어 있으면, 그 원고는 **한 지면에 단이
둘 이상**이라 읽는 순서가 어긋난 것이다. `_작업설정.json`에 `"reading_order": "columns"` 를
넣고 다시 감지한다. 코드는 대사가 열려 있는 동안 숫자만 있는 줄을 건너뛰므로, 설정만
바로잡으면 숫자는 사라진다.

## 성우가 필요 이상으로 늘어난다

`--cast-suggest`가 서브를 3~4명까지 요구하면 **나이 정보를 못 읽고 있는지** 먼저 본다.
`age_bracket()`이 '3세 남짓'·'성인' 같은 표기를 구간으로 바꾸지 못하면 어린이와 어른조차
구별하지 못해, 메인에 몰아줄 수 있는 배역이 전부 서브로 흩어진다. cast 항목의
`age_inline`을 짧고 구체적으로(`3세`, `40대`, `노년`) 채우면 해결된다.
