# 음향 표기 스펙

목적은 하나다. **엔지니어가 원고를 한 문장씩 읽지 않고도 곡을 고를 수 있게 하는 것.**
그래서 씬 카드는 "어디서 / 무슨 일이 / 어떤 느낌으로"를 먼저 말하고, 음악 제안은 그 뒤에 붙는다.

---

> 음향 씬 카드는 **전체 작업본과 성우별 마스터 대본 양쪽에 항상** 들어간다(따로 지시 불필요).

## 씬 카드 (보라색 · 씬이 시작되는 지점)

본문에 얹는 카드는 **씬·장소·상황·분위기 4줄만**. 엔지니어가 문단 덩어리의 분위기를
한눈에 잡게 하는 게 목적이라, 구체적 음악 지시로 카드를 채우지 않는다.

```
♪ 씬: 미주의 미스터리 방송 시청
장소: 미주의 집 거실
상황: 미주가 좋아하는 미제사건 프로그램을 봄
분위기: 일상, 몰입
```

**BGM·앰비언스·효과음·페이드아웃은 본문 카드에 넣지 않는다.** 이 상세 정보는
브리핑의 음향 디자인 표와 `_음향목록.csv`에만 담는다(엔지니어의 세부 참조용).

### 세분화 규칙 (2026-07 사용자 확정 — 촘촘하게)
- **거의 한 페이지당 하나, 또는 1~3문단마다** 씬 카드를 넣는다. 놓치는 구간이 없게.
- 장소·상황·분위기가 바뀌면 반드시 새 씬. 감정이 고조·전환되는 지점도 새 씬.
- **바로 앞 씬과 완전히 똑같을 때만** 이어간다(같은 대화가 몇 페이지 계속). 조금이라도
  달라지면 쪼갠다. 적게 뽑는 것보다 촘촘히 뽑는 게 낫다(장편은 수십~100개 이상도 정상).

### 필드

| 필드 | 내용 | 비고 |
|---|---|---|
| `scene` | 씬을 한눈에 알아볼 짧은 이름 | 필수 |
| `place` | 장소를 구체적으로 | 필수 |
| `situation` | 그 장면에서 무슨 일이 일어나는지 한 문장 | 필수 |
| `mood` | 분위기 2~4개, 쉼표로 | 필수. 선곡의 1차 검색어가 된다 |
| `bgm` | 악기·템포·정서를 구체적으로 | 필수 |
| `ambience` | 길게 깔 환경음 | 없으면 빈 문자열 |
| `note` | 연출 특이점 | **있을 때만.** 없으면 넣지 않는다 |
| `page` / `end_page` | 씬 시작·끝 페이지 | 필수 |
| `start_anchor` | 씬 시작 지점의 본문 문구 8~25자 | 위치 표시용. **반드시 원고에 그대로 있는 문구** |
| `sfx` | 포인트 효과음 목록 | 씬당 0~4개, 꼭 필요한 것만 |

## FADE OUT (파란색 · 음악이 빠져야 할 지점)

```
♪─ FADE OUT: 학교 앞 나무에 식빵이 걸린 아침
3초 페이드아웃 후 무음 1초
```

| 필드 | 내용 |
|---|---|
| `fade_out` | 이 씬 끝에서 음악·효과음이 확실히 빠져야 하면 `true`. 다음 씬으로 그대로 이어지면 `false` |
| `end_anchor` | 그 문구를 읽고 나면 음악이 빠진다. **원고에 그대로 있는 문구** |
| `fade_note` | 어떻게 뺄지 짧게 (예: `3초 페이드아웃 후 무음 1초`, `효과음만 컷, 앰비언스는 유지`) |

**모든 씬에 fade_out을 달지 않는다.** 분위기가 이어지는 씬은 `false`로 두어야
엔지니어가 "여기는 진짜 끊어야 하는 곳"을 구분할 수 있다.

## 씬 끊는 기준

- 씬은 **장소·상황·분위기가 유지되는 덩어리**다. 같은 대화가 몇 페이지 이어지면 한 씬이 여러 페이지에 걸친다.
- 장면 전환·시간 도약·감정 반전이 씬 경계다. 문단이 바뀐다고 자동으로 씬이 바뀌는 건 아니지만,
  1~3문단마다 "앞 씬과 완전히 같은가"를 묻고 조금이라도 다르면 쪼갠다(위 세분화 규칙).
- **씬 수에 상한을 두지 않는다.** 원고 길이에 비례해 넉넉하게 나오는 게 정상이다.
  (v2.2 이전의 "잘게 쪼개지 말 것 · 8~25개가 적당" 기준은 폐기 — 2026-07 대표 확정으로 촘촘하게 뽑는
  쪽으로 바뀌었고, 코드의 `SOUND_SYSTEM` 프롬프트도 촘촘한 쪽을 따른다. v2.4에서 문서 정리.)

## anchor 규칙 (가장 자주 틀리는 곳)

`start_anchor` · `end_anchor` · `sfx.anchor`는 **원고에 글자 그대로 있는 문구를 복사**해야 한다.
요약하거나 지어내면 코드가 위치를 못 찾아 그 메모는 "위치 추정"으로 표시되거나 버려진다.

코드는 앵커를 원문 → 앞 20자 → 앞 12자 순으로 찾아본다.
그래도 못 찾으면 페이지 안 적당한 빈 자리에 `(위치 추정)`을 붙여 놓는다.

## 효과음

- 씬당 0~4개. **꼭 필요한 것만.** 많이 넣을수록 엔지니어가 무시하게 된다.
- 본문 문구 위치에 점선으로 연결해 표시한다.
- 그림책처럼 삽화가 많은 책에서는 박스가 최소 크기로 줄어들거나 여백띠로 밀린다.
