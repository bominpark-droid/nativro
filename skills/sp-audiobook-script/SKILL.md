# SP미디어텍 오디오북 대본 작업

원고 PDF에 **성우용 화자 표시**와 **엔지니어용 음향 가이드**를 얹어 제작 작업본을 만든다.
판단(누가 말했나·어떤 음악인가)은 AI가, 위치·렌더·검증은 결정적 코드가 담당한다.

## 절대 원칙 — 어떤 경우에도 위반 금지

1. **원본 원고는 수정하지 않는다.** 표시는 새 파일에만. 실행 끝에 MD5로 검증하고
   어긋나면 즉시 중단해 보고한다.
2. **원본 글자·삽화를 단 1pt도 가리지 않는다.** 모든 메모는 빈 여백에만 놓는다.
   자리가 없으면 페이지 오른쪽에 흰 여백띠를 덧대(캔버스를 넓혀) 거기에 놓는다.
   원본 위에 겹쳐 쓰는 일은 없다. (형광 하이라이트는 예외 — 글자가 그대로 비쳐 보임)
3. **대사 원문의 토씨 하나 바꾸지 않는다.** 판단만 하고 텍스트는 건드리지 않는다.
4. **확신이 없으면 ★.** 지문 근거 없이 문맥으로 추정한 화자는 `confidence:"low"`로 두어
   ★로 표시되게 한다. 억지로 high를 주지 않는다.
5. **AI 판단은 반드시 `<원고>_AI판단.json`을 거친다.** 렌더는 이 JSON만 읽는다.
   판단 내용을 코드나 브리핑에 직접 써넣지 말 것 — 재현성이 깨진다.

## 절대 원칙에 딸린 세부 (대표 확정)

- 지문 속 의성어·효과음(`“펑!”`)은 **대사가 아니다** — 하이라이트·라벨을 달지 않는다.
- 지문이 "둘이 동시에 말했다"고 하면 화자를 `A+B`로 적어 **두 이름을 함께** 보여 준다.
- 정체가 뒤에 밝혀지는 인물은 **처음부터 최종 이름**으로 적는다(백상아리 → 소소리).
- 캐스팅은 **메인에 최대한 몰아준다.** 나이 구간이 다르면 티키타카라도 메인이 소화한다.
  한 배역에 남녀를 섞지 않는다. 성우 수·성별은 `actors: "auto"`면 코드가 정한다.
- 렌더 끝의 **`[최종검증]`이 전부 ✓ 여야 산출물을 내보낸다.**

## 작업 시작 전 — 반드시 먼저 묻는다

원고마다 대사 표기와 레이아웃이 다르다. 코드를 돌리기 전에
`references/intake.md`의 질문을 던지고, 답을 `<원고>_작업설정.json`에 기록한다.

```bash
python3 scripts/sp_pipeline.py "원고.pdf" --init     # 설정 템플릿 생성
```

질문 없이 바로 돌리면 따옴표 없는 대사를 통째로 놓치거나,
이미 화자명이 인쇄된 책에 라벨을 중복으로 달게 된다.

## 두 가지 버전

### 버전 1 — 전체 작업 (기본)
성우·PD용. 화자 라벨 + 화자별 색 하이라이트 + 음향 + 등장인물표 + 출판사 확인사항.

```bash
python3 scripts/sp_pipeline.py "원고.pdf"
```

산출물: `_대사표시.pdf` · `_검수목록.csv` · `_제작브리핑.md` · `_음향목록.csv` · `_AI판단.json`

### 버전 2 — 음향 전용 (`--sound-only`)
엔지니어용. 화자 표시 없이 씬 카드만. 엔지니어가 원고를 한 문장씩 읽지 않고도
"어느 장소, 어떤 상황, 어떤 분위기"를 보고 선곡할 수 있게 한다.
**음악·효과음이 빠져야 할 지점(FADE OUT)까지 표시**한다.

```bash
python3 scripts/sp_pipeline.py "원고.pdf" --sound-only
```

산출물: `_음향표시.pdf` · `_음향목록.csv` · `_음향브리핑.md` · `_AI판단.json`

### 버전 3 — 성우별 녹음 대본 (`--cast-suggest` → `--master`)
녹음은 **성우 개별 세션**으로 진행하므로, 성우별 색으로 구분한 1장짜리 마스터 대본을 뽑는다. 모든 대사가 담당 성우 색으로 칠해진다(메인=노랑/서브1=하늘/서브2=연보라/서브3=핑크/서브4=초록).

표지에는 **작품 요약(녹음 전 30초 브리핑) + 등장인물표(대사수·성별·나이·특이사항) + 색 범례**가
들어간다. 배역 이름은 성별까지: `메인(여)`, `서브1(남)`.

전체 작업(`_AI판단.json`)이 먼저 있어야 한다(없으면 API를 부르지 않고 중단한다 — v2.4). 그 뒤:

```bash
python3 scripts/sp_pipeline.py "원고.pdf" --cast-suggest   # 캐스팅 제안(검토용 JSON)
# _캐스팅.json 을 열어 검토·수정
python3 scripts/sp_pipeline.py "원고.pdf" --master      # 성우별 색으로 구분한 1장짜리 마스터 대본 생성
```

**캐릭터 식별과 캐스팅 배정은 다른 층**이다. 캐스팅은 사람이 승인한 뒤에만 색이 되고,
성우별 PDF에도 캐릭터 이름 라벨을 남겨(색=성우, 라벨=캐릭터) 오배정을 잡는다.
자세한 규칙과 절차는 `references/casting.md`.

## 두 가지 판단 방식 (버전과 무관하게 조합)

| | 방법 1 — 구독제 토큰 | 방법 2 — API |
|---|---|---|
| API 과금 | **0원** | 원고 분량만큼 |
| 구독 토큰 | 많이 씀 | 거의 안 씀 |
| 절차 | `--export-tasks` → 판단요청서를 읽고 JSON 작성 → `--check` → `--render` | 옵션 없이 실행 |
| 중간 개입 | 쉬움(대화로 교정) | 끝난 뒤 CSV 검수 |

**두 방법의 최종 산출물은 완전히 동일하다.** 판단이 같은 JSON에 모이기 때문이다.

방법 2로 돌릴 때는 Claude Code에게 **"원고 본문은 읽지 마"**를 반드시 붙인다.
이게 빠지면 아끼려던 구독 토큰이 그대로 나간다.

방법 1에서 따옴표 없는 대사(`narrative`)는 **항목 안의 `speaker`가 곧 배정**이다. `assigns`에 넣지
않고 번호도 매기지 않는다 — 코드가 anchor를 확인한 항목만 채택해 순서대로 붙인다(v2.4,
`references/output-rules.md` 3-D).

## 표준 절차

0. (새 컴퓨터에서 처음 한 번) `python3 scripts/sp_pipeline.py --doctor` — 파이썬·라이브러리·한글 폰트·
   `.env`를 점검한다. ✗면 `references/setup.md`대로 잡는다. `scripts/selftest.py`로 전 단계를 무료로 돌려 본다.
1. `--init` → `references/intake.md` 질문 → 답을 `_작업설정.json`에 기록
2. `--detect-only`로 대사 감지 수만 먼저 확인(완전 무료). 숫자가 터무니없으면
   따옴표 스타일이나 label_mode를 다시 본다.
3. 판단(방법 1 또는 2). 방법 1은 `--check`에서 narrative 채택/폐기 건수까지 본다.
4. 렌더 후 **`[최종검증]`이 전부 ✓인지 먼저 보고**, `page.get_pixmap()`으로 PNG를 뽑아 눈으로도 확인한 뒤 보고
5. 보고에 포함: 대사 수 / 매칭 실패 / ★ 건수 / 씬·효과음·페이드아웃 건수 /
   배치 실패 건수 / 여백띠 추가 여부 / 원본 무손상 / 사용한 버전·판단방법

## 실행 위치와 파일 위치 (v2.4)

```bash
python3 /경로/sp-audiobook-script/scripts/sp_pipeline.py "/원고폴더/원고.pdf" [옵션]
```

- 스크립트는 절대경로로, 원고도 경로로. **어느 폴더에서 실행해도 결과는 같다.**
- `_작업설정.json` · `_AI판단.json` · 산출물 · `.env`는 전부 **원고 옆**에서 읽고 쓴다.
  로그 첫 줄 `[작업폴더] …`가 그 폴더다. (v2.3까지는 현재 디렉터리 기준이라 밖에서 실행하면 설정을 못 읽었다)
- 한글 폰트가 없으면 렌더가 중단된다(내장 CJK는 자간이 벌어져 금지). `--doctor`로 확인한다.

## 비용 직결 규칙

- 판단 캐시(`_AI판단.json`)는 원고 MD5가 같으면 자동 재사용된다.
  **레이아웃·색·표만 고칠 때는 절대 재판단하지 말 것.** 그냥 재실행하면 캐시가 먹는다.
  로그에 `[캐시] AI 판단 재사용`이 뜨는지 확인한다.
- 캐시가 있는데 다시 판단하려 하면 **덮어쓰기 전에 사용자에게 확인**한다.
  검수까지 끝낸 판단을 날리면 그 작업이 통째로 사라진다.
- API 키는 **원고 폴더의** `.env` 파일로만. `export ANTHROPIC_API_KEY=...`는 Claude Code 자체를
  구독제가 아닌 종량 과금으로 전환시킨다(`--doctor`가 잡혀 있으면 경고한다).
- `--cast-suggest` / `--master`는 판단 캐시만 쓴다. 캐시가 없으면 **API를 부르지 않고 중단**한다(v2.4).
- 모델을 바꿀 때는 코드가 아니라 `_작업설정.json`의 `model` 또는 `.env`의 `SP_MODEL`을 쓴다.
