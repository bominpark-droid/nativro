# 오디오북 원고 전처리 — Claude Code 운영 지침 v2.4

이 폴더는 SP미디어텍의 오디오북 원고 작업장이다.
원고 PDF에 화자 표시·음향 가이드를 얹어 성우·엔지니어용 제작본을 만든다.

## 절대 원칙 (어떤 경우에도 위반 금지)

1. **원본 원고 PDF는 절대 수정하지 않는다.** 모든 표시는 새 파일에만.
   파이프라인이 MD5로 검증하며, 실패 시 즉시 중단하고 사용자에게 보고한다.
2. **원본 글자·삽화를 단 1pt도 가리지 않는다.** 메모는 빈 여백에만 놓인다.
   자리가 없으면 코드가 자동으로 여백띠를 덧댄다. 이 로직을 우회하지 않는다.
3. **대사 원문을 절대 고치지 않는다.** 판단만 하고 텍스트는 그대로 둔다.
4. **AI 판단은 반드시 `<원고>_AI판단.json`을 거친다.** 판단 주체(API든 Claude Code든)
   와 무관하게 결과는 이 JSON에 저장되고, 렌더는 오직 이 JSON만 읽는다.
5. **작업 전에 반드시 도서 특이점을 확인한다.** `references/intake.md` 참조.
   묻지 않고 바로 돌리면 따옴표 없는 대사를 놓치거나 화자명이 이미 있는 책에
   라벨을 중복으로 달게 된다.

## 새 원고 처리 절차

0. (새 컴퓨터에서 처음 한 번) `python3 scripts/sp_pipeline.py --doctor` — 파이썬·라이브러리·한글 폰트·`.env` 점검.
   ✗면 `references/setup.md`. `scripts/selftest.py`로 전 단계를 무료로 돌려 본다.
1. 원고 PDF를 이 폴더에 넣는다. 작업설정·판단 캐시·산출물·`.env`는 **원고 옆**에서 읽고 쓴다
   (어느 폴더에서 실행해도 같다 — v2.4. 로그 첫 줄 `[작업폴더]` 확인).
2. **버전을 먼저 확인한다**: 전체 작업(화자+음향)인지, 음향 전용(엔지니어용)인지.
3. `python3 scripts/sp_pipeline.py <원고.pdf> --init` → `_작업설정.json` 생성 →
   `references/intake.md`의 질문을 사용자에게 던지고 답을 채운다.
4. `--detect-only`로 대사 감지 수를 먼저 확인(완전 무료). 숫자가 이상하면
   label_mode를 재확인한다.
5. **판단 방식을 사용자에게 묻는다**(토큰 여유 상황에 따라 다름):
   - 방법 1 (구독제, API 과금 0):
     `python3 scripts/sp_pipeline.py <원고.pdf> --export-tasks [--sound-only]`
     → 생성된 `<원고>_판단요청.md`를 읽고 지시대로 `<원고>_AI판단.json` 작성
     → `--check [--sound-only]` (통과할 때까지 수정)
     → `--render [--sound-only]`
   - 방법 2 (API 사용, 구독 토큰 최소):
     `python3 scripts/sp_pipeline.py <원고.pdf> [--sound-only]` 한 줄 실행 후
     **로그만 확인. 원고 본문은 읽지 않는다.**
6. 렌더가 끝나면 **`[최종검증]`이 전부 ✓ 인지 먼저 본다**(산출물을 다시 열어 원본 글자·그림
   전수 대조 + 배정 누락 검사). ✗ 가 하나라도 있으면 산출물을 내보내지 말고 원인부터 잡는다.
   그다음 **`page.get_pixmap()`으로 대표 지면 PNG를 뽑아 눈으로도 확인**한 뒤 보고한다.
7. 보고 시 반드시 포함:
   - 버전(전체/음향전용) · 판단방법(1 or 2)
   - 대사 수 / 매칭 실패 건수 / ★ 건수
   - 씬 수 / 효과음 건수 / 페이드아웃 건수
   - **배치 실패 건수 / 여백띠 추가 여부(폭)**
   - 외국어 읽기 건수 (전체 버전만)
   - 원본 무손상 여부

## 방법 1(구독제 판단)로 작업할 때 지킬 것

- `<원고>_판단요청.md` **안의 지시문을 그대로 따른다.** 임의로 항목을 늘리거나 줄이지 말 것.
- `assigns`는 **id 0번부터 마지막까지 하나도 빠짐없이** 채운다(따옴표·대시로 감지된 대사만).
- 따옴표 없는 대사(`narrative`)는 **항목 안의 `speaker`·`confidence`·`reason`이 곧 배정**이다.
  `assigns`에 넣지 않고 번호도 매기지 않는다 — 코드가 anchor를 확인한 항목만 채택해 순서대로 붙인다
  (v2.4. 예전 방식은 폐기 항목이 생기면 뒤 배정이 한 칸씩 밀렸다).
- **대사 원문을 절대 고치지 않는다.**
- `src_md5`는 요청서에 적힌 값을 **복사**한다. 직접 계산하거나 지어내지 말 것.
- 확신이 없으면 억지로 high를 주지 말고 `confidence:"low"`로 둔다.
- anchor(씬 시작·끝, 효과음 위치)는 **원고에 그대로 있는 문구를 복사**한다.
  요약하거나 지어내면 위치를 못 잡아 그 메모가 버려진다.
- 대사가 많으면 100~200개씩 나눠 판단해 JSON을 병합한다(한 응답에 몰면 잘림).
- 판단 후 반드시 `--check` → `--render` 순으로 진행한다. `--check`는 narrative 채택/폐기 목록도
  보여 준다 — 폐기(원고에 없는 문구) 항목은 anchor를 원문 그대로 고친다.
- **원고 PDF를 통째로 읽지 않는다.** 반드시 `--export-tasks`로 만든 판단요청서만 읽는다.
  같은 내용을 여러 번 읽으면 구독 토큰이 몇 배로 나간다.

## 방법 2(API)로 작업할 때 지킬 것

- `python3 scripts/sp_pipeline.py <원고.pdf>` 한 줄만 실행하고 **로그만 본다.**
- **"원고 본문은 읽지 마"를 스스로에게도 적용한다.** 확인한다며 원고를 읽으면
  아끼려던 구독 토큰이 그대로 나간다.
- 크레딧 소진 에러가 나면 코드 문제가 아니다. 콘솔 충전 또는 방법 1 전환을 안내한다.

## 표시하지 않는 것 · 함께 적는 것 (2026-08-02 대표 확정)

- **지문 속 의성어·효과음**(`“펑!”`, `“우르르 쾅쾅!”`)은 대사가 아니다. 하이라이트·라벨 금지.
  화자를 `(대사아님)`으로 두면 코드가 표시에서 뺀다. 그 소리는 음향 씬 카드의 SFX로 전달한다.
- **동시 발화**는 화자를 `A+B` 로 적어 라벨에 두 이름이 함께 나오게 한다(두 성우 겹쳐 녹음).
  판별: 그런 지문 앞에 대사가 1줄이면 동시, 2줄이면 지문의 **이름 순서 = 말한 순서**.
- **정체가 나중에 밝혀지는 인물**은 처음부터 최종 이름으로 적는다(백상아리 → 소소리).
- **라벨은 어떤 경우에도 버리지 않는다.** 자리가 없으면 여백띠에 놓되 대사 앞부분을 함께 적는다.

## 성우별 녹음 대본 (녹음은 성우 개별 세션)

녹음은 항상 성우 개별 세션으로 진행하므로, 최종 산출은 **성우별 색으로 구분한 1장짜리 마스터 대본**다.
전체 작업으로 `_AI판단.json`이 먼저 있어야 한다. 그 뒤:

1. `python3 scripts/sp_pipeline.py <원고.pdf> --cast-suggest`
   → 규칙 기반 캐스팅 초안 `<원고>_캐스팅.json` + 요약 출력.
2. **사용자가 `_캐스팅.json`을 검토·수정**한다(캐릭터를 배역에 재배치).
   출력된 '주고받는 대화가 잦은 쌍'과 '경고'를 근거로 안내한다.
3. `python3 scripts/sp_pipeline.py <원고.pdf> --master`
   → `<원고>_마스터대본.pdf` 1장 생성(모든 성우 색 구분).

지킬 것:
- **한 성우는 한 성별만.** 어린이·여자 역할=여성 성우, 남자 역할=남성 성우. 배역에 남녀 혼합 금지.
- **같은 성별 안에서 메인에 최대한 몰아준다**(티키타카 아니거나 나이 구간이 다르면 메인).
- **마스터 대본에는 음향 씬 카드(보라색)도 항상 포함**된다(따로 지시 불필요).
- 화자 이름 라벨은 이름 앞에 (성별, 나이)를 작게 붙인다. 예: (남성, 20대) 홍길동.
- **캐스팅은 사람이 승인한 뒤에만 색이 된다.** `--cast-suggest`는 제안일 뿐,
  자동으로 성우 PDF를 만들지 않는다. 반드시 검토 단계를 거치게 안내한다.
- 성우별 PDF에도 **캐릭터 이름 라벨을 유지**한다(색=성우, 라벨=캐릭터 → 오배정 감지).
- **★ 불확실 대사**는 특정 성우 색으로 강제하지 않고 표지의 '확인 필요' 목록에 올린다.
  녹음 전 그 대사만 검수하면 된다.
- 어느 배역에도 없는 캐릭터가 있으면 `--master`가 경고한다. 반드시 배정하게 안내한다.
- `--cast-suggest`·`--master`는 판단 캐시만 쓴다. 캐시가 없으면 **API를 부르지 않고 중단**한다(v2.4).
- `label_mode: "highlight-only"` 책은 마스터 대본에도 라벨을 달지 않는다(v2.4).
- 성우 수는 `_작업설정.json`의 `actors`. **기본 `"auto"` — 코드가 규칙을 지킬 수 있는 최소
  인원과 배역별 성별을 스스로 정한다.** 대표가 인원을 지정하면 그 숫자를 넣는다.
- **배역 이름에 성별을 함께 쓴다**: `메인(여)`, `서브1(남)`. 표지 범례·로그 모두 이 표기.
- **마스터 대본 표지에는 작품 요약(30초 브리핑)과 등장인물표(대사수·성별·나이·특이사항)가
  반드시 들어간다.** 규칙은 `references/casting.md`, `references/output-rules.md` 4-A.

## AI 판단 캐시 (비용 직결 — 반드시 지킬 것)

- 재실행 시 원고 MD5가 같으면 자동 재사용되어 **API 비용 0**으로 다시 렌더한다.
- **브리핑 레이아웃·표·색만 고칠 때는 절대 재판단하지 말 것.** 그냥 재실행하면 캐시가 먹는다.
  로그에 `[캐시] AI 판단 재사용`이 뜨는지 확인한다.
- 재판단을 강제하려면 그 json을 지운다.
- 캐시가 이미 있는데 다시 판단하려 하면 **덮어쓰기 전에 사용자에게 확인**한다.
  검수 끝난 판단을 날리면 그 작업이 통째로 사라진다.

## 배치 원칙 (v2.0 핵심)

- 모든 메모는 결정적 코드가 빈 자리를 찾아 놓는다. **좌표를 직접 지정하지 않는다.**
- 자리가 없으면 코드가 자동으로 여백띠를 붙인다(`gutter: "auto"`, 기본 150pt).
  이 동작을 임의로 끄지 않는다 — 사용자가 `_작업설정.json`에서 `"off"`로 명시한 경우만 예외.
- 렌더 로그의 `[배치] 자리 못 잡음 N건`을 확인하고, 남아 있으면 사용자에게 보고한다
  (CSV·브리핑에는 텍스트로 남으므로 정보 손실은 없지만, 본문 표시가 빠진 것이므로 알려야 한다).

## 필요 설정

- 라이브러리: 스킬 폴더에서 `pip install -r requirements.txt` (pymupdf · anthropic.
  방법 1만 쓰면 anthropic은 없어도 된다)
- **한글 폰트**: 없으면 렌더가 중단된다(내장 CJK는 자간이 벌어져 금지). 탐색 순서는
  `.env`의 `SP_KFONT` → 작업설정 `font` → 스킬의 `assets/fonts/` → 시스템 폰트.
  `--doctor`가 어느 폰트가 잡히는지 알려준다. 자세한 것은 `references/setup.md`.
- 방법 2(API)만: **원고 폴더**의 `.env` 파일에 `ANTHROPIC_API_KEY=sk-ant-...` 한 줄.
  (환경변수 export 방식은 Claude Code 자체를 API 과금으로 전환시키므로 .env를 쓴다)
- 모델을 바꾸려면 작업설정 `model` 또는 `.env`의 `SP_MODEL=` — 코드를 고치지 않는다.

## 조정값 (scripts/sp_pipeline.py 상단)

- `MODEL`: 기본 `claude-sonnet-4-6`(작업설정 `model`·`.env` `SP_MODEL`로 덮어쓴다). 절감안
  `claude-haiku-4-5`는 컨텍스트가 200K라 장편 원고 전문을 한 번에 넣으면 넘칠 수 있다 —
  정확도 비교 검증 후 전환할 것
- `CHUNK`: 기본 40. "응답 잘림" 에러 시 30 → 25로 낮춘다.
- `LABEL_FS` / `SND_FS`: 라벨/음향 메모 글자 크기.
- `GUTTER_W`: 여백띠 기본 폭(pt). 그림책처럼 삽화가 많으면 늘려야 할 수 있다.

## 알려진 특성과 대응

- **한글 폰트 없음**: v2.4부터 조용히 내장 폰트로 폴백하지 않고 렌더를 중단한다. `--doctor`로 확인하고
  `references/setup.md`대로 폰트를 잡는다(`assets/fonts/`에 넣는 게 가장 확실).
- **폰트 깨진 페이지**: `[진단] 깨짐 [...]`에 나오는 페이지는 대사 감지에서 제외된다.
  목차·장식 페이지면 무시해도 되지만, 본문이 깨졌으면 사용자에게 반드시 알린다.
- **스캔본(텍스트 레이어 없음)**: 파이프라인이 자동 중단한다. OCR 선행 안내.
- **따옴표 스타일**: "" / "" / 「」 를 자동 감지한다. 그 외 스타일이면 `QUOTE_PAIRS`에 추가.
- **한 지면에 단이 둘 이상인 조판(그림책·펼침면)**: `_작업설정.json`에
  `"reading_order": "columns"`. 안 켜면 단 끝에서 열린 따옴표가 다음 쪽 문장을 끌어와
  **서로 다른 화자의 대사가 한 덩어리로 붙는다.** 증상은 대사 안에 쪽번호 숫자가 섞이는 것.
- **쪽번호 밀림**: 브리핑이 앞에 붙어 뷰어 쪽번호가 원본보다 밀린다. 지면 인쇄
  쪽번호 기준으로 소통하라는 안내가 브리핑 1쪽에 자동 포함된다.
- **★ 대사**: 지문 근거 없는 추정. 사용자가 CSV에서 검수한다. 요청하면 해당 대사의
  앞뒤 원문을 보여주며 검수를 돕되, 판단을 강요하지 않는다.

자세한 규칙은 `references/output-rules.md`, 음향 스펙은 `references/sound-spec.md`,
에러 대응은 `references/troubleshooting.md` 참조.
